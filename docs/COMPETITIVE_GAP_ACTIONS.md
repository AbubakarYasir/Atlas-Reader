# Competitive workflow audit and implementation actions

Reviewed 2026-09-27. Status: planning requirements; implementation is not claimed.

## Evidence and limits

The following primary sources were reviewed. They describe product behavior, not measured Atlas superiority. Platform, edition and release differences must be recorded during hands-on comparison.

- [Xournal++ PDF workflow](https://xournalpp.github.io/guide/pdfs/): separate editable journal and PDF background; export has preservation limitations. Learn from its explicit local-document relationship and test our own portability independently.
- [Xournal++ input preferences](https://xournalpp.github.io/guide/config/preferences/): pressure and temporary stylus-button tool switching inform N6 input tests.
- [Foxit Reader feature matrix](https://www.foxit.com/pdf-reader/comparison/): desktop controls and platform differences inform discoverability and keyboard qualification.
- [Foxit accessibility report](https://www.foxit.com/compliance/foxit-editor-suite-accessibility-conformance/): evaluate complete keyboard and assistive-technology journeys; a vendor report is not proof for Atlas.
- [Acrobat viewing preferences](https://helpx.adobe.com/ca/acrobat/using/viewing-pdfs-viewing-preferences.html): focused reading and reversible workspace modes inform N4.
- [Acrobat accessibility](https://helpx.adobe.com/acrobat/using/accessibility-features-pdfs.html): document reading order, reflow and spoken reading expose gaps beyond accessible toolbar buttons.
- [Librera project](https://github.com/foobnix/LibreraReader) and [reading workflows](https://librera.mobi/): multi-format discovery, book preferences and library sorting inform shared book behavior. Android/mainline documentation must not be assumed to describe every F-Droid build.

Local executable metadata confirms Foxit PDF Editor 2026.1.1.36485 and Xournal++ 1.3.5+dev are installed. Foxit's Start screen was inspected, but native automation did not complete a repeatable document workflow. The owner supplied an installed Foxit document screenshot, an installed Xournal++ blank-journal screenshot, Xournal++ feature illustrations/text, and separate Foxit Reader and Editor marketing extracts. These establish audit topics and visible controls, not measured interaction, latency, preservation or accessibility results. Marketing illustrations do not establish the installed version's capabilities. Xournal++ development-only functionality must be labelled when compared with stable Atlas. Personal document screenshots, titles and paths are not committed.

The owner explicitly clarified that the purpose is to close feature and quality gaps before 2.0, not copy designs. No competitor layout, ribbon, colors, icons or artwork is adopted by this audit. Vendor superlatives, prices, compliance claims and performance claims are not Atlas requirements or independently verified findings. Reader and paid Editor capabilities must not be conflated.

## Coverage of the owner-supplied references

This is the disposition of the reference topics, not a promise to implement every competitor feature. Required actions above are binding; explicit exclusions below stay visible in the release limitations. Changing an exclusion requires owner scope approval and a delivery/test owner before implementation.

| Reference topic | Atlas 2.0 disposition and accountable stage |
|---|---|
| Reading, tabs, search, thumbnails, bookmarks, fit/zoom, reading direction | Required N4/N5; C02–C06 add missing navigation, document accessibility and safety checks. |
| Pressure pen, eraser, highlighter, width/color, selection, undo, touch separation | Required N6 within qualified hardware; C07 supplies physical-input and recovery evidence. |
| Xournal++ layers and page previews | Previews N4; annotation visibility C16/N6. Arbitrary notebook layers, paper templates and notebook page authoring are excluded from 2.0; local annotation storage must remain independently recoverable. |
| Shapes, arrows, image insertion, snapping, LaTeX | Typed notes and line/arrow/rectangle/ellipse markup required N6/C19. E2 owns original text/image editing and offline equations. Full diagramming, snapping and full notebook authoring remain excluded. |
| Custom toolbars and Lua plugins | Essential tool presets/state N6; arbitrary toolbar editors and executable plugin systems excluded from 2.0. No scripting trust surface is added merely for parity. |
| Audio linked to handwritten objects | Excluded from 2.0; it requires consent/recording controls, media storage, backup and portable-export semantics. Offline read-aloud C11 is a different feature and does not satisfy audio-note parity. |
| Print, metadata, covers, file management | Required N7; preserve source bytes for reading/printing and distinguish metadata edits from filename changes. |
| AcroForm/XFA filling versus form creation | Ordinary non-scripted AcroForm filling required N7/C20. E3 adds AcroForm authoring and E5 offline signature fields. XFA, scripts/calculations and submit actions excluded; C15 covers safe unsupported behavior. |
| Handwritten signatures, certificate signing, signature verification, eSign services | E5 requires visible marks and local-certificate signing, with evidence-limited offline verification. Online services excluded. N5 detection alone never establishes validity. |
| PDF text/image editing, page rearrangement/merge/split, Office conversion | E1 requires page organization; E2 requires original text/image editing. Office conversion remains excluded. Preserve unrelated content and research references. |
| OCR, redaction, document-version comparison | E4 requires secure redaction and independent removal tests. OCR and automated version comparison remain excluded; N5 revision detection is not a comparison engine. |
| Cloud storage, shared reviews, DMS, enterprise deployment | Excluded from 2.0; N8 local backup and N11 normal Windows installation remain required. No account/network dependency or enterprise-policy claims. |
| AI chat, summarization, translation, generated outlines/images | Excluded from 2.0. No document upload, cloud credits or unverified research output introduced. |
| Security, accessibility, cross-platform availability | Security and Windows accessibility are release gates, not marketing badges. Other operating systems remain separately staged after Windows 2.0; no untested platform support claim. |

Every P2 or candidate decision must state include/defer/reject, rationale, owner, tests and release impact. N11 checks that required actions have evidence and exclusions appear in user-facing limitations. A feature is not completed by adding its name to this document.

## Explicit follow-up decisions

The owner delegated the offline launch-scope decision on 2026-09-27: C17–C22 are required pre-2.0 additions, superseding the earlier candidate/deferred treatment of parallel reading, simplified text view, collections/tags, basic shapes/free text and ordinary form filling. Full-fidelity arbitrary PDF reflow is not promised; C18 has a defined qualification corpus and honest fallback.

Dictionaries, series-specific management and additional DjVu/FB2/TXT/RTF/HTML/DOCX support remain post-2.0 candidates. At F3 closure, record ranked follow-up candidates with user value, dependencies and tests. The owner subsequently confirmed E1–E5 offline editing, form authoring, equations, redaction and signatures before 2.0; [the binding roadmap](OFFLINE_EDITING_ROADMAP.md) supersedes earlier exclusions. OCR, audio notebooks, Office conversion and online/collaboration remain excluded. No online or collaboration feature may be introduced through a dependency or a convenience option.

## Repeatable comparison procedure

At each relevant stage, select redistributable fixtures or private disposable copies. Record product/edition/version, fixture hash, hardware, task, exact steps, observed result, Atlas result, difference and action ID. Compare N4 navigation with Foxit/Acrobat, N5/N6 preservation with an independent PDF reader, N6 pen behavior with Xournal++, and F1–F3 library/reading with an appropriate mature format reader. Record unsupported tasks as not applicable with reasons. Do not substitute a documentation review for a hands-on result. Store sanitized results in the owning stage evidence file; never commit personal book contents or paths.
