### v1 sampler defect discovered

English iteration 6 reported only **2.48 MiB working set** and **0.434 MiB private memory**, while its startup/shutdown metrics showed a much longer process lifecycle. That is not a credible live Atlas memory sample.

Root cause in the harness: `WaitForInputIdle(5000)` is not a reliable Qt Quick readiness signal. It can block until after Atlas's auto-shutdown window and then sample a process that has already exited or is exiting.

Therefore:

- iteration 6 memory/CPU values are **invalid** and must not be used as product evidence;
- the v1 summary memory/CPU averages are retained only as raw historical output;
- corrected English warm process values from iterations 2–5 are approximately:
  - working set: **44.722 MiB** average;
  - private memory: **26.797 MiB** average;
  - normalized one-second CPU: **1.302%** average;
  - resize p99: **18.407 ms** average when the anomalous sixth run is excluded.

The v2 harness removes `WaitForInputIdle`, waits for Atlas's own first-frame metric, refuses to count memory/CPU if the process is no longer alive, and reports sample validity explicitly.

### Startup gate discovered

The physical run also exposed a real N1 performance issue rather than merely a harness issue.

Even ignoring the invalid process-memory sample, ordinary warm English first frames in iterations 2–5 were about **1.79–2.23 s**, and Arabic warm runs were about **1.76–1.93 s**. The provisional performance contract targets:

- warm empty-shell first frame: **<800 ms p95** on the baseline SSD;
- cold empty-shell first frame: **<1.5 s p95**.

Attempt 1 therefore **does not pass the N1 startup target**. N1 remains In progress; we do not normalize a slow empty shell merely because it feels visually fine after appearing.

## Corrective N1 measurement build

The corrective build keeps product scope unchanged and addresses measurement/startup cost before N2:

1. replace runtime-selected Fusion controls with compile-time `QtQuick.Controls.Basic`, Qt's lightweight/max-performance Controls baseline;
2. keep Atlas palette/theme behavior on top of that cross-platform base;
3. record startup checkpoints for:
   - `QGuiApplication` ready;
   - arguments ready;
   - metrics ready;
   - QML engine ready;
   - immediately before QML load;
   - QML loaded;
   - first swapped frame;
4. record device pixel ratio, logical/physical DPI and actual QQuickWindow refresh rate;
5. capture storage devices and active Windows power scheme in the PowerShell report;
6. bind packaged reports to the CI build commit from `N1_BUILD_INFO.txt`;
7. replace the invalid input-idle sampler with first-frame-aware live-process sampling;
8. report warm first-frame p50/p95 as well as averages.

The corrective build must pass strict Debug + Release CI and portable `windeployqt` staging before a second physical run is accepted as evidence.

- deterministic window-resize frame interval p50/p95/p99;
- device pixel ratio/logical DPI/refresh rate;
- Windows/CPU/GPU/RAM plus available storage/power-scheme data;

The first process launch remains labeled a **cold candidate**, not a guaranteed laboratory cold-cache run. Do not compare numbers gathered under different cache, power, refresh, VM, or build conditions as if they were identical.

## N1 interpretation

N1 establishes a **zero-feature cost floor**, not a marketing performance claim. Future checkpoints compare against this baseline so we can identify whether PDF rendering, indexing, bookmarks, or annotations introduce regressions.

A regression discovered later must be attributed to a named subsystem rather than dismissed as “Qt overhead.” Equally, an already-slow empty shell is not an acceptable baseline merely because later features have not yet been added.

## Acceptance rule

N1 cannot be Accepted until:

1. Debug + Release strict CI passes on the corrective branch head;
2. the target-machine corrective baseline contains valid real measurements;
3. startup meets the accepted N1 threshold, or any remaining deviation has a measured root cause and an explicit owner-approved performance tradeoff;
4. English/Arabic + 100%/200% qualification is recorded sufficiently to avoid an unknown scaling regression;
5. no PDF/database dependency has slipped into the tree;
6. the owner explicitly records PASS.
