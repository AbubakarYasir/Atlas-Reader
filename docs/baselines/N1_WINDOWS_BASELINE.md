## Canonical build

See `../TOOLCHAIN.md`.

Minimum accepted evidence:

- Release build;
- canonical MSVC/Qt baseline or explicitly noted compatibility kit;
- actual physical Windows 11 machine, not only a CI VM;
- commit SHA recorded;
- display refresh/DPI noted;
- English/LTR and Arabic/RTL shell exercised;
- 100% and 200% Windows scale checked manually;
- clean repeated startup/shutdown;
- no PDF/database code present.

## Build

```powershell
$env:CMAKE_PREFIX_PATH = 'C:\Qt\6.10.3\msvc2022_64'
cmake --preset windows-msvc2022
cmake --build --preset windows-release
ctest --preset windows-release
```

If the executable cannot locate Qt DLLs when launched directly, prepend the kit's `bin` directory or pass it to the harness with `-QtBin`.

## Automated local measurement

English/system theme:

```powershell
.\tools\bench\measure-windows-shell.ps1 `
  -Iterations 6 `
  -Language en `
  -Theme system `
  -QtBin C:\Qt\6.10.3\msvc2022_64\bin
```

Arabic/dark smoke measurement:

```powershell
.\tools\bench\measure-windows-shell.ps1 `
  -Iterations 3 `
  -Language ar `
  -Theme dark `
  -QtBin C:\Qt\6.10.3\msvc2022_64\bin
```

The harness records:

- process launch → input-idle candidate;
- QML loaded time;
- first swapped frame time;
- working set/private memory after settling;
- one-second normalized CPU sample;
- deterministic window-resize frame interval p50/p95/p99;
- clean shutdown timestamp.

The first process launch is labeled a **cold candidate**, not a guaranteed laboratory cold-cache run. Do not compare numbers gathered under different cache, power, refresh, VM, or build conditions as if they were identical.

## N1 interpretation

N1 is establishing a **zero-feature cost floor**, not publishing a marketing performance claim. Future checkpoints compare against this baseline so we can identify whether PDF rendering, indexing, bookmarks, or annotations introduce regressions.

A regression discovered later must be attributed to a named subsystem rather than being dismissed as “Qt overhead.”
