## N5.2 Local overlay — 2026-11-03

Status: **Implemented** (automated checks; Windows CI green at `e411225`). Decision: [ADR-0008](../decisions/ADR-0008-bookmark-overlay-and-location-envelope.md) (Proposed until `N5 PASS`).

- `src/core/bookmarks/LocationEnvelope` (pure C++): `atlas-location/1;scheme=pdf;page=…;label=…;kind=…;left/top/right/bottom/zoom`. Kinds XYZ, Fit, FitH, FitV, FitR, FitB, FitBH, FitBV with per-kind coordinate rules; coordinates are fractions 0–1 of the displayed page (origin top-left); zoom 0–64; numbers written with `std::to_chars` (exact, locale-free); labels and extension values percent-encoded UTF-8; unknown keys kept in order; newer major version → `unsupportedVersion`, unknown scheme → `unsupportedScheme`, both kept as raw text by callers; 8 KiB limit.
- `src/core/bookmarks/BookmarkOverlay` (pure C++): `BookmarkNode`, `BaseSnapshot`, `StorageState`, `StorageEvent`; one 22-row transition table; `EmbedProof` (written, validated, reopened, re-indexed, new revision) required for `embedVerified`; `validateNode`, `validateTree` (unique IDs, one document, parents present, no cycles, depth ≤ 256, contiguous sibling positions), `validateAgainstBase` ("no false Embedded"), `embeddedNodesFromBase`, strict UTF-8 check, random 128-bit IDs.
- Schema 5 (`SqliteLibraryIndex` migration 5): `bookmark_overlays`, `bookmark_base_snapshots`, `bookmark_base_nodes`, `bookmark_nodes` (with `CHECK`s for state, base key and conflict fields, tombstone column), `bookmark_node_tags`. Adds tables only.
- `src/app/bookmarks/SqliteBookmarkOverlay`: opens an existing profile only (schema ≥ 5, Atlas application ID); `load` in one read transaction; `adoptBase` stores the first outline and creates Embedded nodes (earlier local nodes move after them), and reports `unchanged` or `needsReconcile` without writing for any later outline; `apply` checks the revision, transitions, base-key rules, "hidden and conflict nodes can't be edited", "source nodes are hidden, not removed", tree and base rules, then writes in one `BEGIN IMMEDIATE` transaction (WAL, `synchronous = FULL`); removals become tombstones and their IDs are retired; `documentsWithLocalWork` lists documents to offer after a restart.
- Tests: `atlas_bookmark_overlay` (UTF-8 edge cases; envelope round trips for every kind, Arabic labels, exact doubles, extensions; 17 malformed and 2 unsupported inputs; all 66 state × event pairs against an independently written table; every missing proof step; tree, depth, cycle, position and base rules). `atlas_bookmark_store` (no profile created on its own; non-Atlas database refused; schema-4 profile upgraded with library data intact; base adoption, unchanged and needs-reconcile; every state persisted across reopen; exact bytes for Arabic with spaces, Urdu with harakat and ZWJ, emoji, U+0000; tags in order with duplicates; a newer envelope kept; false Embedded, illegal transitions, editing hidden nodes, removing source nodes, orphaning children, stale revisions and reused IDs refused; tombstone row present; 10,000 nodes with 197-sibling move; crash recovery: a child process ends with `std::_Exit` before `COMMIT` in `apply` and in `adoptBase`, and right after a commit without closing; afterwards `integrity_check` is `ok` and no foreign key dangles). ## N5.3 slice 1: editing engine — 2026-11-03

Status: **Implemented** (automated checks; Windows CI green at `07df65d`). No UI yet: the Bookmarks panel is slice 2.

- `src/core/bookmarks/BookmarkEditor` (pure C++): `create`, `rename`, `setLocation`, `setNotes`, `move` (reorder, nest, outdent), `remove` (local subtree removed; a PDF bookmark is hidden instead; a local folder holding a PDF bookmark is refused with `containsSourceNodes`), `setHidden`, `setEmbedRequested`; `undo`/`redo` (500 steps) with `confirm`/`discardPending`/`reset` around the worker write; refusals `busy`, `unhideFirst`, `resolveFirst`, `cycle`, `tooDeep`, `notFromPdf`, `notLocal`, `historyStale` and the field rules. A PDF bookmark becomes `LocalOverride` when edited and `Embedded` again when its title, destination, parent and relative order match the PDF once more; notes and tags never change the state. Undo updates only the touched sibling lists.
- Rule refinement (DATA_AND_SAFETY, ADR-0008): Embedded siblings must keep the PDF's **relative** order; local bookmarks may sit between them. Before, an absolute-position comparison would have marked every following PDF bookmark as changed when a local one was inserted above them.
- Repository: `OverlayChangeSet::restores` brings a removed local node back from its tombstone with the same ID (undo of a removal); refused as `idInUse`, `restoreWithoutRecord` or `restoreWithoutTombstone` otherwise. Each write is checked by `OverlayTreeIndex`, kept per document between writes and valid only while the stored revision is unchanged; on any failure it is dropped and rebuilt. Debug builds re-run `validateStructure` + `validateAgainstBase` on every accepted write and fail if they disagree.
- `src/core/bookmarks/BookmarkSearchIndex`: titles, notes and tags through `normalizeForSearch` (N4.5): case folded, harakat/tatweel/joiners ignored, alef/yeh/kaf/heh variants unified; reading order kept; hidden bookmarks only on request; result limit.
- Tests: `atlas_bookmark_editor` (every command against a real profile, automatic states, refusals, undo of all 7 commands back to the original outline and redo forward, removal restored with the same IDs, failed write discarded and reloaded, store restore rules, Arabic/English search, notes and tags hits). `atlas_bookmark_overlay` gains the relative-order cases and a 6,000-round differential fuzz: random valid and invalid changes (moves, nesting, cycles, bad positions, removals that orphan, renames, state flips, double base claims, hide/unhide) — the incremental verdict equals the full rules every time and refused changes leave the index unchanged (over 1,000 of each outcome). All earlier tests unchanged and passing.
- Benchmark `atlas_n5_bookmark_benchmark` (10,000-node Arabic/English outline, 4 levels, real profile): runs in Windows CI Release and fails the job if a gate is missed. Linux container (2 threads, g++ 13 `-O2`, SQLite 3.45.1), two runs: search p95 0.09–0.11 ms (gate < 100 ms); editor command p95 0.21–0.22 ms and undo p95 0.29–0.30 ms (gate < 2 ms); write on the worker p50 2.8 ms / p95 5.8–6.3 ms; load 30 ms; editor build 10 ms; search index build 4 ms. The benchmark first caught undo at 11 ms p95 (full index rebuild) and writes at 50–65 ms (whole-tree reload and check); both were fixed before this commit.
- Local run: all four bookmark/index test programs pass under AddressSanitizer and UBSan; new code is warning-free with `-Wconversion -Wsign-conversion -Wshadow` (GCC 13) and `-Wshadow-all -Wconversion` (Clang 18).
- Windows CI `41586451488` at `07df65d` (MSVC, warnings as errors): Debug and Release 51/51 tests pass, including `atlas_bookmark_overlay` (fuzz), `atlas_bookmark_store` and `atlas_bookmark_editor`; the Debug run exercises the full-rules cross-check on every write. All six N2 PDF workflows green. **Windows Release benchmark** (GitHub Windows runner, 2 hardware threads, 10,000 nodes; p50 / p95 / p99 ms): search 0.099 / 0.175 / 0.203 (gate < 100: PASS); editor command 0.075 / 0.199 / 0.218 and undo 0.164 / 0.305 / 0.328 (gate < 2: PASS); write on the worker 2.47 / 9.12 / 12.64; load 33.8 / 37.2; editor build 13.1; search index build 5.3 / 5.5; outline adoption 221. A shared CI runner, not owner hardware: the owner-review build repeats it on the owner's PC.

## N5.3 slice 2: Bookmarks panel — 2026-11-03

Status: **Implemented** (automated checks and rendered self-review; Windows CI evidence added when the run completes). Owner checks (Windows display scaling, Narrator, real IME typing) are in the end-of-N5 review.

- `src/app/bookmarks/BookmarkService`: one worker thread (`atlas-bookmarks`) owns the profile's `SqliteLibraryIndex` (opened first, so the profile is migrated) and `SqliteBookmarkOverlay`; `open` (identity, outline → base snapshot, adoption, load), `write`, `reload`; answers return on the UI thread only while the receiver exists; the destructor finishes queued writes and closes the database on the worker. `baseFromOutline`: outline entries (key, parent key, position, title, page, point as fractions of the unrotated page, zoom) → base snapshot; a point off the page becomes Fit; an outline breaking the overlay limits is refused whole.
- `SqliteLibraryIndex::documentsAtPath`: exact generic-UTF-8 path, ASCII case-insensitive only if nothing matches exactly. Panel rule: one document → editable; none → `notInLibrary`; several → `ambiguous`; both read-only with the PDF's outline.
- `src/app/bookmarks/BookmarkModel` (QML `BookmarkModel`, one per tab): visible rows (expanded, depth first; hidden ones only on request) or search hits with breadcrumbs; incremental row updates (unchanged head and tail kept); commands add/rename/setDestination/setNotes/remove/moveUp/moveDown/indent/outdent/setHidden/undo/redo; edits confirm in memory at once and their writes queue in order (each expects the revision the previous one makes); a failed write drops the queue and reloads what is stored (`reloaded`); detaching or destroying still sends queued writes; refusals are signalled with a stable reason; current-page bookmark; counts.
- Reader: `DocumentTextWorker` adds key, parent key, position, point (fractions) and zoom to each outline entry; `ReaderViewport::goToNormalized` and `viewLocation`.
- UI: `BookmarksPanel.qml` rewritten (header: add, delete, one expand/collapse toggle, options; find field; read-only and changed-outline notices; tree with state icons, inline rename, current-page bar; "N hidden" toggle; bookmark menu sized to its longest item).
