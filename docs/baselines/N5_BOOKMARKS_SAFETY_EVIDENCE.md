## N5.3 slice 1: editing engine — 2026-11-03

Status: **Implemented** (automated checks; Windows CI green at `07df65d`). No UI yet: the Bookmarks panel is slice 2.

- `src/core/bookmarks/BookmarkEditor` (pure C++): `create`, `rename`, `setLocation`, `setNotes`, `move` (reorder, nest, outdent), `remove` (local subtree removed; a PDF bookmark is hidden instead; a local folder holding a PDF bookmark is refused with `containsSourceNodes`), `setHidden`, `setEmbedRequested`; `undo`/`redo` (500 steps) with `confirm`/`discardPending`/`reset` around the worker write; refusals `busy`, `unhideFirst`, `resolveFirst`, `cycle`, `tooDeep`, `notFromPdf`, `notLocal`, `historyStale` and the field rules. A PDF bookmark becomes `LocalOverride` when edited and `Embedded` again when its title, destination, parent and relative order match the PDF once more; notes and tags never change the state. Undo updates only the touched sibling lists.
- Rule refinement (DATA_AND_SAFETY, ADR-0008): Embedded siblings must keep the PDF's **relative** order; local bookmarks may sit between them. Before, an absolute-position comparison would have marked every following PDF bookmark as changed when a local one was inserted above them.
- Repository: `OverlayChangeSet::restores` brings a removed local node back from its tombstone with the same ID (undo of a removal); refused as `idInUse`, `restoreWithoutRecord` or `restoreWithoutTombstone` otherwise. Each write is checked by `OverlayTreeIndex`, kept per document between writes and valid only while the stored revision is unchanged; on any failure it is dropped and rebuilt. Debug builds re-run `validateStructure` + `validateAgainstBase` on every accepted write and fail if they disagree.
- `src/core/bookmarks/BookmarkSearchIndex`: titles, notes and tags through `normalizeForSearch` (N4.5): case folded, harakat/tatweel/joiners ignored, alef/yeh/kaf/heh variants unified; reading order kept; hidden bookmarks only on request; result limit.
- Tests: `atlas_bookmark_editor` (every command against a real profile, automatic states, refusals, undo of all 7 commands back to the original outline and redo forward, removal restored with the same IDs, failed write discarded and reloaded, store restore rules, Arabic/English search, notes and tags hits). `atlas_bookmark_overlay` gains the relative-order cases and a 6,000-round differential fuzz: random valid and invalid changes (moves, nesting, cycles, bad positions, removals that orphan, renames, state flips, double base claims, hide/unhide) — the incremental verdict equals the full rules every time and refused changes leave the index unchanged (over 1,000 of each outcome). All earlier tests unchanged and passing.
